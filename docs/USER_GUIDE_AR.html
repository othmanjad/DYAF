نظام مراقبة الحركات المالية (AML / Fraud TMS) — كل قاعدة كشف هي جملة SELECT

إصدار 2.0 · لمحللي الامتثال ومكافحة الاحتيال · لا يتطلب أي معرفة برمجية

المحتويات المبدأ العام 1) Rule — بيانات القاعدة 2) FROM · WINDOW — المصدر والنافذة الزمنية 3) WHERE — فلترة السجلات 4) GROUP BY — مستوى التجميع 5) SELECT — التجميعات المسماة 6) HAVING — شرط إطلاق التنبيه 7) أزرار التنفيذ أمثلة كاملة مشروحة (3) نصائح وأخطاء شائعة

المبدأ العام

كل قاعدة في النظام هي استعلام SELECT:
FROM من أين تقرأ الحركات ← WHERE أي الحركات تدخل الحساب ← GROUP BY على مستوى مَن تجمّع ← SELECT ماذا تحسب ← HAVING متى يصدر التنبيه.
الشاشة مرتبة بهذا الترتيب من الأعلى إلى الأسفل — عبِّئها بالترتيب تحصل على قاعدة كاملة.
مهم — نموذج القيد المزدوج: كل حركة مالية مخزنة سجلين: سجل بمنظور المرسل (is_debit = true) وسجل بمنظور المستقبل (is_debit = false). حقل wallet_id هو «صاحب المنظور»، وcounterparty_wallet_id هو الطرف الآخر، وكل صفات محفظة صاحب المنظور متاحة بحقول تبدأ بـ wallet_ مثل wallet_residence_country وwallet_pep_status.

1) Rule — بيانات القاعدة

الحقلمعناه
Nameاسم القاعدة كما سيظهر في التنبيهات وكتالوج القواعد.
Scenario Refمرجع اختياري لربط القاعدة بسيناريو الكتالوج (TM-01 …) لأغراض التقارير.
Risk Scoreدرجة المخاطر (0–100) التي تُلحق بكل تنبيه تولده هذه القاعدة.
Severityشدة التنبيه: Low / Medium / High / Critical — تُستخدم لترتيب أولوية التحقيق.
Frequencyكل كم يشغّل المجدولُ القاعدةَ تلقائياً (كل ساعة، كل يوم …).
Descriptionوصف حر يشرح ماذا تكشف القاعدة — يظهر لفريق التحقيق.

2) FROM · WINDOW — المصدر والنافذة الزمنية

  • Datasource: الفهرس الذي تُقرأ منه السجلات (الافتراضي transactions). أي مصدر جديد يضيفه مسؤول النظام من تبويب Data يظهر هنا تلقائياً.
  • Time Window: الفترة التي تفحصها القاعدة عند كل تشغيل: آخر يوم، آخر 7 أيام، آخر 60 يوماً… القاعدة لا ترى أي سجل أقدم من النافذة.
قاعدة ذهبية: عند مقارنة فترتين (شهر حالي مقابل شهر سابق) يجب أن تغطي النافذة الفترتين معاً — أي 60 يوماً.

3) WHERE — فلترة السجلات (اختياري)

يحدد أي السجلات تدخل الحساب أصلاً. كل شرط = حقل + مشغّل + قيمة:

العنصرالتفاصيل
الحقلقائمة منسدلة بكل حقول المصدر (تُكتشف تلقائياً من الفهرس)، وتشمل حقول المحفظة المدموجة wallet_* والحقول المحسوبة.
المشغّلeq, neq, gt, gte, lt, lte, in, not_in, between, contains, starts_with, exists, missing
القيمة • الحقول النصية: تُقترح القيم الموجودة فعلاً في الفهرس (قائمة اقتراحات).
• حقول التاريخ: قائمة أوقات نسبية جاهزة (now-7d، now-30d…) أو منتقي تاريخ دقيق.
• القوائم المُدارة: اكتب @اسم_القائمة مثل @high_risk_countries.
+ Groupمجموعات شروط متداخلة بمنطق AND / OR / NOT، والسحب بالفأرة يعيد الترتيب.

4) GROUP BY — مستوى التجميع

الاختيارالنتيجة
بدون حقولوضع المطابقة: تنبيه مستقل لكل سجل يطابق WHERE (لا حاجة لأقسام SELECT وHAVING) — الأنسب للحدود الثابتة الفورية.
حقل واحد مثل wallet_idتنبيه واحد لكل عميل تتحقق فيه شروط HAVING.
عدة حقول مثل wallet_id + merchant_country كيان مركّب — تنبيه لكل «عميل × دولة» (مفيد لكشف الممرات الجديدة).

5) SELECT — التجميعات المسماة

هنا تعرّف ماذا تحسب لكل كيان. كل سطر تجميع يتكون من:

العنصرالتفاصيل
الاسماسم حر تشير به في HAVING، مثل debit_sum أو this_month.
الدالةcount عدد · count_distinct عدد القيم المميزة · sum مجموع · avg متوسط · min/max أدنى/أقصى.
الحقلمطلوب لكل الدوال عدا count (مثل amount).
FILTERأهم مفهوم في الشاشة: شروط تخص هذا التجميع وحده. sum(amount) بفلتر is_debit = true = مجموع الصادر فقط؛ وcount بفلتر executed_at ≥ now-30d = عدد حركات آخر شهر فقط.
أضف أي عدد من التجميعات — المقارنة بينها تتم في القسم التالي HAVING.

6) HAVING — شرط إطلاق التنبيه

تعبير حر يقارن التجميعات ببعضها أو بأرقام. كل سطر:

تجميع + مشغّل (> ≥ < ≤ == !=) + الطرف الأيمن: رقم ثابت أو k × تجميع آخر

  • المضاعِف k يتيح شروطاً مثل «أكبر من ثلاثة أضعاف المعدل»: total > 3 × declared.
  • الأسطر تُربط بـ AND / OR.
  • للمتقدمين: فعِّل advanced text واكتب التعبير مباشرة، مثل recent >= 1 AND prior == 0.

7) أزرار التنفيذ

الزروظيفته
Validateفحص سلامة القاعدة (حقول موجودة؟ تعبير HAVING سليم؟) دون تنفيذ.
Preview SQL + ES Queryعرض جملة SQL المقروءة + استعلام Elasticsearch الفعلي — للمراجعة والتوثيق.
Test Ruleتشغيل تجريبي فوري: كم سجلاً قُرئ، كم كياناً قُيّم، مَن سيُنبَّه وبأي قيم — دون حفظ أي تنبيه. استخدمه دائماً لمعايرة الحدود قبل التفعيل.
Save Ruleحفظ القاعدة (كل حفظ يرفع رقم الإصدار تلقائياً)، ثم فعِّلها من تبويب Rules.

أمثلة كاملة مشروحة

المثال 1 تجميع + مقارنة «العميل الذي صادره اليوم أكثر من وارده»

القسمالإعداد
WINDOW1 days
WHEREفارغ — نريد كل حركات العميل
GROUP BYwallet_id
SELECTdebit_sum = sum(amount) بفلتر is_debit = true
credit_sum = sum(amount) بفلتر is_debit = false
HAVINGdebit_sum > credit_sum

الشرح: فلترا is_debit يفصلان الصادر عن الوارد لنفس العميل خلال اليوم، وHAVING يقارنهما. في نتيجة الاختبار يظهر W-1001 بقيم debit_sum = 114,207 مقابل credit_sum = 710 — مطابق.
تنويعة: لمقارنة العدد بدل القيمة، غيّر الدالة من sum إلى count في التجميعين.

المثال 2 مقارنة فترتين «الأردني الذي عدد حركاته هذا الشهر أكثر من الشهر السابق»

القسمالإعداد
WINDOW60 days — تغطي الشهرين معاً
WHEREwallet_residence_country eq JO
GROUP BYwallet_id
SELECTthis_month = count بفلتر executed_at gte now-30d
last_month = count بفلتر executed_at lt now-30d
HAVINGthis_month > last_month

الشرح: نمط «مقارنة فترتين»: فلتران زمنيان على نفس الحد now-30d يقسمان نافذة الستين يوماً إلى شهر حالي وشهر سابق. شرط WHERE يجعل القاعدة تقيّم عملاء الأردن فقط.

تحسينان: أضف سطر HAVING ثانياً last_month > 0 لاستبعاد العملاء الجدد، أو ارفع المضاعِف إلى 1.5 لاشتراط نمو حقيقي (this_month > 1.5 × last_month).

المثال 3 وضع المطابقة «تنبيه فوري لكل حركة صادرة أكبر من 50,000»

القسمالإعداد
WINDOW7 days
WHEREis_debit eq true AND amount gt 50000
GROUP BY / SELECT / HAVINGفارغة كلها

الشرح: عندما تترك GROUP BY وSELECT فارغين تعمل القاعدة بوضع «المطابقة المباشرة»: تنبيه مستقل لكل سجل حققت شروطه WHERE، مع لقطة كاملة من الحركة داخل التنبيه. في الاختبار: سجل واحد مطابق (حوالة الـ 75,000).

نصائح وأخطاء شائعة

#النصيحة
1النافذة يجب أن تغطي أبعد فلتر زمني. فلتر executed_at < now-30d مع نافذة 7 أيام لن يجد أي سجل أبداً — النافذة تُقرأ أولاً ثم تُطبق الفلاتر داخلها.
2انتبه للقيد المزدوج. بدون فلتر is_debit يُحسب سجلا الحركة معاً (منظور المرسل + منظور المستقبل). أضف is_debit = true عندما تقصد الصادر فقط.
3Test قبل Save دائماً. زر Test يعرض قيمة كل تجميع لكل عميل — أفضل وسيلة لمعايرة الحدود وتقدير حجم التنبيهات قبل التفعيل.
4تعلّم من القوالب الجاهزة. تبويب Rules يحوي كتالوج السيناريوهات TM-01…TM-12 محمّلاً مسبقاً (معطلاً) — افتح أي قاعدة بزر Edit لترى كيف بُنيت.
5استخدم القوائم المُدارة. بدل تكرار قائمة الدول في كل قاعدة، عرّفها مرة واحدة من تبويب Data واستخدم @اسم_القائمة — تعديل القائمة يسري على كل القواعد.
6الحقول المحسوبة للمعادلات. شرط على ناتج معادلة (مثل «مبلغ مدوّر»)؟ عرّف حقلاً محسوباً من تبويب Data (is_round = amount % 1000 == 0) واستخدمه كأي حقل.
7القاعدة المحفوظة لا تعمل حتى تفعّلها. بعد Save انتقل لتبويب Rules وفعّل مفتاح Enabled — عندها يشغّلها المجدول حسب Frequency، والتنبيهات تظهر في تبويب Alerts.
